# 一、设计目标

## 1.1 从产品定位推导设计命题

contentHub 的产品定位是 **「选题资产工作台（Topic Asset Studio）」**——把一次选题的资料、图片、说明沉淀为可复用资产，再以版式引擎派生各平台合规产物。

这决定了一件事：**它不是内容生产工具，是内容资产管理 + 派生的工作台。** 用户在这里做的不是"写文章"，而是"管资产、看形态、做决策"。

由此得到三条设计命题：

| # | 命题 | 对设计的直接约束 |
|---|---|---|
| **命题一** | 主对象是「主题资产」，不是「文章」 | 信息架构以 Topic 为轴心，素材、版式、产物、投递全部挂靠在主题详情下，而非平铺为独立功能页 |
| **命题二** | 产物形态多、平台规则硬 | 「能用什么、不能用什么」必须在界面上显式呈现，不能让用户把平台限制误判为产品缺陷（对应计划书 2.4 平台能力矩阵） |
| **命题三** | 发布动作不可逆、有平台红线 | 所有投递路径必须带**前置校验 + 人工二次确认**，UI 不允许出现"一键发布"的暗示 |

## 1.2 设计原则（P0，冲突时按序让位）

| 优先级 | 原则 | 说明 | 反例（禁止） |
|---|---|---|---|
| P0-1 | **状态永远可见** | 主题状态 / 发布状态 / 渲染 / 产物 / 凭据**五类状态机**在任何列表、详情、卡片上都可见，不允许"静默失败" | 渲染失败后列表只显示一个空缩略图，无失败标识 |
| P0-2 | **资产先于排版** | 主题详情是唯一主工作面，版式与平台是它的派生视图 | 把"排版"做成独立一级菜单，与主题库平级 |
| P0-3 | **预览保真** | 预览区必须模拟真实阅读环境（浅色底、真实宽度），不得被后台暗色主题污染 | 预览区沿用暗色卡片，导致文字灰度和图片色彩判断失真 |
| P0-4 | **规则前置** | 平台规格、字数区间、图片比例在录入时即时校验，不等到投递才报错 | 提交时弹出 20 条错误清单 |
| P0-5 | **不可逆动作减速** | 破坏性/不可撤回动作需要明确文字确认，不用"是/否"，用动作动词 | `确定要发布吗？[是][否]` |

## 1.3 设计目标与衡量方式

| 维度 | 目标 | 衡量方式 |
|---|---|---|
| 认知负荷 | 用户无需记忆页面位置即可完成六步链路 | 新用户首次完成「建主题 → 出产物」无需外部指导 |
| 状态透明 | 任意时刻可回答"这个主题走到哪一步了" | 主题列表页单行内可见 `status` + `publishStatus` + 最近渲染结果 |
| 错误预防 | 平台规格类错误在提交前拦截率 100% | 无"投递后被平台拒"的案例 |
| 一致性 | 复用基线的视觉与组件资产，降低学习与维护成本 | 组件复用率 ≥ 70%；Token 与 webserver 同源 |
| 可达性 | 全流程键盘可操作，AA 级对比度 | axe / Lighthouse 无障碍得分 ≥ 90 |

## 1.4 设计红线（不做）

- ❌ 不做营销式首页 / 大 Banner / 情绪化插画——这是内部工具，不是官网。
- ❌ 不做"一键全平台发布"的任何视觉暗示（文案、图标、按钮组）。
- ❌ 不在预览区使用暗色主题。
- ❌ 不用颜色单独承载状态语义（必须色 + 图标 + 文字三重编码）。
- ❌ 不引入第二套图标体系（统一 Font Awesome，与基线一致）。

# 二、用户场景

## 2.1 角色定义

角色取自后端 `ROLE_CMD_LIST` 裁剪结果，前端**按角色隐藏端点对应的入口**，而非操作后报错。

| 角色 | 典型身份 | 核心诉求 | 界面裁剪 |
|---|---|---|---|
| **运营编辑**（Operator） | 内容运营 | 建主题、配素材、渲染、投递 | 全部内容链路可见；无账号管理、无审计 |
| **主编 / 审核**（Reviewer） | 内容负责人 | 审合规、批投递 | 只读主题、可执行合规校验与投递确认；不可改素材 |
| **资产管理员**（AssetAdmin） | 素材维护 | 上传、去重、清理素材 | 素材图库全权；主题只读 |
| **系统管理员**（Admin） | 技术/运维 | 账号凭据、审计、监控 | 全部可见，含账号、审计、设置 |

> **设计约定**：无权限的功能**整体隐藏**，不显示禁用态（避免暴露系统结构）；仅在有权限但当前不可用时才用禁用态 + Tooltip 说明原因。

## 2.2 核心场景

| ID | 场景 | 用户目标 | 关键痛点（设计要解决） | 成功标准 |
|---|---|---|---|---|
| **S1** | 新建选题资产 | 把一次选题的资料结构化落库 | 字段多（标题/简介/详述/作者/地点/来源/时期/标签），一次性铺开易疲劳 | 分区渐进填完，必填项实时提示，字数实时计数 |
| **S2** | 配图与图注 | 上传多图并逐图写说明、排序 | 图和说明分离管理，排序后说明错位 | 图片与图注成对编辑，拖拽排序，图注即 `alt` |
| **S3** | 选版式 × 平台 | 判断"这套内容用什么形态发哪里" | 不清楚平台能力边界，选错才发现不支持 | 平台能力矩阵内联展示，不支持项直接灰显并说明原因 |
| **S4** | 渲染与等待 | 触发渲染后知道进度与结果 | 渲染异步，不知道跑到哪、失败为什么 | 任务列表带状态与耗时，失败可展开错误原因并重试 |
| **S5** | 合规校验与修正 | 知道哪里不合规、怎么改 | 报错只给结果不给位置 | 返回问题清单，敏感词回显命中位置并高亮 |
| **S6** | 投递与留痕 | 推草稿 / 导素材包，且可追溯 | 怕误发、怕重复推送 | 二次确认 + 60 秒撤销窗 + 发布记录可查 |

## 2.3 场景 → 页面映射

| 场景 | 主页面 | 辅助页面 |
|---|---|---|
| S1 新建选题资产 | P-03 主题编辑 | P-02 主题列表、P-01 工作台 |
| S2 配图与图注 | P-03 主题编辑 · 素材区 | P-04 素材图库 |
| S3 选版式 × 平台 | P-05 版式与平台 | — |
| S4 渲染与等待 | P-06 渲染任务 | P-07 产物台账 |
| S5 合规校验 | P-09 合规校验 | P-08 预览 |
| S6 投递与留痕 | P-10 投递 | P-11 账号管理、P-12 审计日志 |

**关键设计决策（P0-3「预览保真」）**：

| 区域 | 背景 | 说明 |
|---|---|---|
| 预览画布外（后台） | `bg/base` `#030712` | 保持暗色，与后台统一 |
| 手机框内（内容区） | **`preview/bg` `#FFFFFF`** | **强制浅色**，模拟真实阅读环境 |
| 设备外框 | `#374151` + 24px 圆角 | 视觉上明确"这是一个隔离容器" |

**理由**：公众号与小红书的真实阅读场景是浅色底。若预览沿用暗色，会导致两个错误判断——① 正文灰度、对比度判断失真；② 图片色彩在暗底对比下显得比实际更饱和。这是排版类产品的**口碑生死线**（对应 R-08），预览必须保真。

**小红书两种预览模式**（对应版式 `swipe_v1` / `longimage_v1`）

| 模式 | 呈现 | 交互 |
|---|---|---|
| **滑动多图集**（`swipe_v1`） | 单张 1080×1440 卡片置于手机框内，底部显示 `1 / 8` 序号点 | `←` / `→` 方向键、点击左右箭头或点击序号点切换 |
| **长图**（`longimage_v1`） | 手机框内纵向滚动长图，右侧显示高度刻度 | 滚动 |

> **不做真实手势模拟**：桌面端用键盘 / 箭头切换即可模拟"逐张翻页"，不需要在预览区复刻 App 的滑动手势。真实左右滑动体验在**真机验收**环节确认（对应开发计划 7.8 节第 11 项）。
>
> 滑动多图集预览需同时显示**比例一致性提示**：若各图比例不一致，序号点上方给出 `⚠ 比例不一致，App 内滑动会跳动`。

│  产物      HTML · 8 图 · 3200 字              │
│                                              │
│  ⚠ 本次为草稿投递，群发需在公众号后台手动完成  │
│  ⚠ 今日剩余推送次数：1 次                     │

│              [取消]  [确认推送草稿]            │  ← 动词而非"确定"

**设计要点**：
- 确认按钮用**动作动词**（"确认推送草稿"）而非"确定"，降低误点率。
- 弹窗内**复述关键参数**（主题/账号/版式/产物），让用户在点之前完成最后一次核对。
- 明确写出"群发需手动完成"——这是产品能力边界，也是合规红线（对应结论一「推送 ≠ 发布」）。
- 显示**剩余推送配额**（订阅号 1 次/天），因为误发不可撤回。
- 投递成功后 Toast 带 **60 秒撤销窗**入口（对应 P3-3）。

# 五、组件规范

## 5.1 组件分层

```
L0 Token 层    颜色 / 字号 / 间距 / 圆角 / 阴影   → Tailwind config + Element Plus CSS 变量
L1 基础组件    Button Input Select Checkbox Table Tabs Modal Drawer Toast Tooltip Pagination
L2 业务组件    StateBadge PlatformChip AssetThumb LayoutCard AssetOrderStrip SpecChecker WordCounter PreviewFrame ConfirmPublish
L3 页面模板    列表页模板 / 详情页模板 / 工作台模板
```

**与 Element Plus 的分工（P0 约定）**：

决策依据：**组件库与工程基线 `museum/webserver` 同源**（基线即 `Vue 3 + Element Plus + Tailwind`），复用成本最低。

- **Element Plus 负责交互复杂度**：表格排序筛选、日期选择、级联、树、穿梭框、消息提示（`ElMessage` / `ElMessageBox`）——与基线 `app.use(ElementPlus)` + 全量图标注册的既有用法一致。
- **Tailwind 负责布局与间距**：所有 `flex/grid/gap/padding` 一律用 Tailwind 工具类。
- **视觉 Token 单点注入**：通过 `--el-*` CSS 变量传入本规范 Token（见 10.4），**禁止**在业务组件里硬编码颜色值，也**禁止**用 Tailwind 类去覆盖 Element Plus 组件内部样式（避免版本升级断裂）。
- **冲突处理**：Element Plus 组件默认样式与本规范冲突时，改 `--el-*` 变量，不改组件。
- **暗色模式**：引入 `element-plus/theme-chalk/dark/css-vars.css` 并在 `<html>` 上加 `dark` class 作为基底，再用本规范 Token 覆盖变量值。

## 6.1 五类状态机（界面必须可见）

```
主题 status（`ch_topic.status`）
  DRAFT ──► RENDERING ──► RENDERED ──► PUBLISHED
    │           │            │             │
    └───────────┴────────────┴─────────────┴──► ARCHIVED

主题 publishStatus（`ch_topic.publishStatus`，与 status 并列展示的独立字段）
  UNPUBLISHED ──► DRAFTED ──► PUBLISHED
       └──────────────┴──► FAILED ──(重试)──► DRAFTED

渲染任务 jobStatus
  PENDING ──► RUNNING ──┬──► DONE
                        └──► FAILED ──(重试)──► PENDING

产物 artifactStatus
  READY ──(过期)──► EXPIRED ──(清理)──► 删除

## 6.3 关键交互流程

### 流程一：主题资产 → 产物 → 投递（主链路）

```
P-02 列表 ──[＋新建]──► P-03 编辑

                          │ [发起渲染]  ← 校验：素材 ≥1、版式已选、比例统一、数量 ≤18
                          ▼
                       P-06 渲染任务（PENDING → RUNNING → DONE）
                          ▼
                       Tab4 产物（READY，可预览/下载）
                          ▼
                       P-09 合规校验（阻断项必须清零）
                          │ [标记通过]
                          ▼

                          ▼
                       投递成功 ──► Toast + 60s 撤销窗 + 发布记录写入
```

### 流程二：平台不支持路径的拦截

用户在小红书平台选择"发布"类动作时——该动作**不存在**。界面只提供「导出素材包 ZIP」。若用户从其他路径产生误解，用引导性 Tooltip 说明：*"小红书禁止第三方自动发布，本产品仅提供素材包导出"*。**不设计禁用按钮**，因为不存在的能力不应占据界面（原则 14）。

### 流程三：编辑冲突 / 凭据失效的降级

| 情况 | 交互 |
|---|---|
| 凭据 `INVALID` | 投递入口灰显 + 顶部 ConflictBanner 提示"账号凭据已失效，请到账号管理重新授权" + 直达链接 |
| 渲染队列积压 | P-06 顶部提示"当前队列 N 个任务，预计等待 M 分钟"（基于队列长度估算，不伪装精确进度） |
| 产物 `EXPIRED` | 产物卡片显示过期徽章 + `[重新渲染]` 主操作，禁用下载 |

## 6.4 动效规范

| 类型 | 时长 | 缓动 | 说明 |
|---|---|---|---|
| 微交互（hover / 按钮） | 150ms | `ease-out` | 与基线 `transition-colors` 一致 |
| 背景色过渡 | 200ms | `ease-out` | 表格行 hover、卡片 hover |
| 弹窗出现 | 250ms | `ease-out` | 背景 `opacity 0→1` + 内容 `scale(0.96→1)` |
| 弹窗关闭 | 180ms | `ease-in` | 反向 |
| 抽屉滑入 | 250ms | `cubic-bezier(0.4,0,0.2,1)` | 从右侧 |
| Tab 指示器滑动 | 250ms | `ease-out` | 下划线平滑位移 |
| 列表项进入 | 240ms，依序延迟 40ms | `ease-out` | 最多应用于前 10 项，后续直接显示 |
| 状态脉冲 | 2s | `ease-in-out` 循环 | 仅用于 `RUNNING` 状态点 |
| 骨架屏 shimmer | 1.5s | `linear` 循环 | — |

**禁止的动效**：视差滚动、渐变背景动画、粒子/撒花、内容自动轮播。这是工具型后台，动效只服务于状态感知，不做情绪表达。

| 场景 | 反馈方式 | 是否需二次确认 |

| **导出素材包** | Toast 绿 + 浏览器下载 | 否（可逆、无平台动作） |

| 删除被引用素材 | — | **是**（列出引用主题） |
| 批量删除 | — | **是**（显示数量） |
| 撤销投递 | 60s 内 Toast 内提供「撤销」 | 撤销本身不加确认 |

> **二次确认文案规范**：标题 = 动作 + 对象；正文 = 关键参数复述 + 后果说明；按钮 = 动词（"确认推送草稿" / "确认删除"），禁用"是/否/确定/取消"这种无语义组合。

## 7.6 暗色 / 浅色模式策略 ● 关键决策

**结论：contentHub 主界面采用暗色单一主题，不提供浅色模式切换。**

| 维度 | 决策 | 理由 |
|---|---|---|
| 主界面 | **仅暗色** | ① 与 `museum/webserver` 基线一致，零迁移成本；② 长时段编辑场景，暗色降低视觉疲劳；③ 内容运营常与图片为伴，暗色界面让素材缩略图更突出 |
| 预览区 | **强制浅色** | 模拟真实阅读环境，保证灰度与色彩判断保真（原则 P0-3） |
| 是否做主题切换 | **不做** | 双主题需维护两套 Token 与两套对比度校验，收益低、成本高；本规范预留 Token 语义层，未来可扩展 |

**隔离边界实现约定（P0）**

```
┌─ app (data-theme="dark")  ──────────────────┐
│  侧栏 / 顶栏 / 卡片 / 表格   → 暗色 Token     │
│                                              │
│  ┌─ preview-scope (data-theme="light") ──┐  │
│  │  手机框内全部内容 → 浅色 Token          │  │
│  │  ⚠ 该作用域内禁止引用任何暗色 Token     │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

- 预览作用域用**独立 CSS 变量命名空间**（`--preview-*`），不复用 `--bg-*`。
- 预览区内的组件**不继承**应用主题；Element Plus 在预览作用域内通过**独立 CSS 变量作用域**重置为浅色（`.preview-scope` 内覆盖 `--el-bg-color` / `--el-text-color-primary` / `--el-border-color` 等），**不依赖 `html.dark`**。
- 代码审查检查项：`PreviewFrame` 子树中不得出现 `bg-surface` / `text/primary` 等应用级 Token。

## 8.4 移动端能力边界（P0 声明）

**XS 断点不承诺完整的编辑能力**，这是有意的范围控制：

| 能力 | 移动端支持 |
|---|---|
| 浏览主题 / 产物 / 发布记录 | ✅ 完整 |
| 查看预览、查看合规问题 | ✅ 完整 |
| 编辑标题 / 简介等短字段 | ✅ 支持 |
| 编辑详述长文本 | ⚠️ 支持但提示"建议在桌面端编辑" |
| **图片排序 / 素材上传批量管理** | ❌ 提示到桌面端 |
| **发起渲染 / 投递确认** | ❌ 提示到桌面端 |

**理由**：渲染与投递是低频率、高后果动作，在移动端误触代价高（订阅号 1 次/天）。**能力边界必须显式告知**，而不是让用户在窄屏上艰难完成。

## 8.5 响应式实现约定

- **优先用 CSS 布局能力**：`flex-wrap` / `grid-auto-fit` / `minmax()`，减少断点硬编码。
- **容器查询优先于视口查询**：详情页辅助栏等组件用 `@container`，使其在抽屉中也能正确降级。
- **断点只在布局结构变化处设置**，不为微调字号而设断点（用 `clamp()` 处理）。
- **图片用 `srcset` + 宽度描述符**，素材缩略图提供 320 / 640 / 1280 三档（对齐后端 `THUMBNAIL_SIZE = 640` 与 `MAX_PIC_SIZE = 1920`）。

# 九、无障碍要求

## 9.1 目标等级

**WCAG 2.1 Level AA**。AA 级项为验收底线，AAA 级不强制但鼓励。

## 9.2 对比度

| 内容类型 | 最低要求 | 本规范实现 |
|---|---|---|
| 正文文字（< 18px） | 4.5:1 | `text/primary` 对 `bg/surface` ≈ 13.6:1 ✅ |
| 大号文字（≥ 18px 或 ≥ 14px Bold） | 3:1 | `H1/H2` 均达标 ✅ |
| 次要文字 | 4.5:1 | `text/secondary` ≈ 5.9:1 ✅ |
| 三级文字 / 占位符 | 3:1 | `text/tertiary` ≈ 3.4:1 ✅（**仅限非关键信息**） |
| 图标（功能性） | 3:1 | 跟随文字层级 ✅ |
| 边框 / 分割线（非文字） | 3:1 | `border/default` 对 `bg/surface` ≈ 1.9:1 ⚠️ **不达 3:1** |

> **⚠️ 已知偏差与处理**：`border/default` 对相邻背景的对比度低于 3:1（WCAG 1.4.11 要求 3:1）。**处理方式**：卡片/容器的边界**不依赖边框单独传达信息**——层级同时通过背景色差异（`bg/base` → `bg/surface` 有明显明度差）和留白表达，边框仅作强化。聚焦态使用 `primary` 色（高对比）满足 1.4.11。

**校验方式**：每次 Token 变更后跑一次对比度脚本，输出所有"文字色 × 背景色"组合的对比度矩阵，低于阈值的组合直接失败。

## 9.3 键盘可达性

| 要求 | 实现 |
|---|---|
| 全流程可键盘操作 | 所有交互元素为原生 `button` / `a` / `input`，或显式 `tabindex="0"` + 键盘事件 |
| Tab 顺序 = 视觉顺序 | 不使用 `tabindex` 正值调整顺序 |
| 焦点永远可见 | `outline: 2px solid #3B82F6; outline-offset: 2px`，**禁止 `outline: none`** |
| 焦点管理与页面切换 | 弹窗打开时焦点移入弹窗并**锁定在弹窗内**（focus trap）；关闭后焦点**回到触发元素** |
| 快捷键 | `Ctrl/Cmd + S` 保存；`Esc` 关闭弹窗/抽屉；`/` 聚焦搜索框；`Ctrl/Cmd + Enter` 提交当前表单 |
| 跳过导航 | 首个 Tab 停靠点为"跳到主内容"链接（视觉隐藏，聚焦时显示） |
| 拖拽排序的替代方案 | 每个可拖拽项提供「上移 / 下移」按钮（**P0 要求**，不可只做拖拽） |

## 9.4 语义与 ARIA

| 场景 | 要求 |
|---|---|
| 页面结构 | 使用 `<header>` `<nav>` `<main>` `<aside>` `<footer>`；`<main>` 每页唯一 |
| 页面标题 | 路由切换时更新 `document.title` 与 `h1`，供屏幕阅读器朗读 |
| 表格 | `<th scope="col">` / `scope="row"`；复杂表格用 `aria-describedby` 关联说明 |
| 表单 | 每个控件有 `<label for>`；必填用 `required` + `aria-required="true"`；错误用 `aria-invalid="true"` + `aria-describedby` 指向错误文案 |
| 字数计数 | `aria-live="polite"`，在接近上限时播报（避免每次输入都播报） |
| 状态变化 | 渲染任务状态变化用 `role="status"` + `aria-live="polite"` |
| 阻断性错误 | `role="alert"` + `aria-live="assertive"`（谨慎使用，避免打断） |
| 加载态 | 容器加 `aria-busy="true"` |
| 图标按钮 | 必须有 `aria-label`（如 `aria-label="删除主题 敦煌壁画的色谱研究"`） |
| 弹窗 | `role="dialog"` + `aria-modal="true"` + `aria-labelledby` 指向标题 |
| 抽屉 | 同弹窗，`role="dialog"` |

## 9.5 色觉障碍适配（P0）

**核心规则：任何状态不得仅靠颜色区分**（WCAG 1.4.1 不依赖颜色）。

本规范采用**三重编码 + 形状差异化**：

| 状态 | 颜色 | 图标形状 | 文字 |
|---|---|---|---|
| 成功 / 通过 | 绿 | ✓ 实心对勾 | 明确文字 |
| 警告 | 橙 | ⚠ 三角 | 明确文字 |
| 失败 / 阻断 | 红 | ✕ 叉号 | 明确文字 |
| 运行中 | 蓝 | ◐ 半圆 + 脉冲 | 明确文字 |
| 排队中 | 灰 | ○ 空心圆 | 明确文字 |
| 已过期 | 橙 | ⚠ 三角 | 明确文字 |

**灰度测试**：设计稿必须通过灰度模式检查——`success`（绿 #10B981）与 `danger`（红 #EF4444）在灰度下亮度接近，因此**必须依赖图标形状区分**，这是本规范要求图标与颜色并存的原因。

## 9.6 其他无障碍要求

| 项 | 要求 |
|---|---|
| 触控目标尺寸 | ≥ 44×44px CSS 像素（移动断点下）；桌面端 ≥ 32×32px |
| 文本缩放 | 浏览器缩放至 200% 时布局不破坏、不出现水平滚动 |
| 动效降低 | 尊重 `prefers-reduced-motion: reduce`，关闭所有非必要动效（脉冲、shimmer、列表进入） |
| 图片替代文本 | 素材图片的 `alt` **默认取图注（caption）字段**；无图注时提示填写，不允许留空 |
| 错误信息可读 | 错误提示给出「哪里错了 + 怎么改」，不给错误码（除审计日志页） |
| 时间格式 | 显示相对时间（"2 小时前"）时，`title` 属性提供绝对时间；屏幕阅读器朗读绝对时间 |
| 语言标记 | `<html lang="zh-CN">`；英文片段用 `<span lang="en">` |
| 剪切板操作 | 复制 `topicCode` / `fileID` 用按钮实现，不依赖用户手动选中文本 |

**Token 落地方式（P0）**：

```
