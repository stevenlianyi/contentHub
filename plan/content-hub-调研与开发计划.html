P0 · 结论一：全自动发布这条路，在国内主流平台已被政策封死

微信公众号：2025 年 7 月起，微信官方回收了个人主体账号、企业未认证账号的 freepublish/submit（发布）接口权限。个人订阅号现在通过 API 最多只能把文章推进草稿箱，最后一下「群发」必须人到后台点。服务号（认证）与已认证企业订阅号不受影响。

小红书：官方开放平台的笔记发布接口仅面向通过资质审核的企业主体/品牌/服务商开放；且 2026 年 AI 治理规则明确把「AI 工具自动生成笔记、自动定时发布」列为红线行为，判定即限流、禁言 7–30 天，重度（全账号 AI 托管）直接永久封禁并连带同设备/同实名矩阵账号。

⇒ 你的需求 [4]「生成内容可自动推送至目标平台」必须重新定义：推送 ≠ 发布。产品应交付「一键推送到草稿箱 / 一键生成可发布的素材包」，发布动作保留人工确认。

结论二：这恰恰是市场空白，不是退路

市面上的工具是割裂的：排版工具（135编辑器/秀米）只管把一篇文章排得好看；分发工具（蚁小二/融媒宝/Wechatsync）只管把成品搬运到各平台；CMS（Strapi/Payload）只管存结构化数据。没有人做「结构化主题资产 → 多版式渲染 → 各平台合规产物 → 通道投递」这条完整流水线。

你的差异化正在于此：以「主题」为核心资产（而非以「文章」为核心），一份素材自动派生公众号长文 + 小红书图集 + 长图三种形态。分发工具做不到这点，因为它们没有内容模型。

结论三：真正的技术难点是渲染引擎，不是发布

三个目标平台的产物形态完全不同，必须抽象成一个版式中间层：

  • 微信公众号：只能接受内联样式的 HTML，外部图片链接一律不显示（必须先用素材接口转存到 mmbiz.qpic.cn），class 会被清洗；「左右轮播」需用 SVG 交互实现，而 SVG 在部分场景不稳，需图集兜底。
  • 小红书：只接受图片/视频，不接受 HTML。「左右轮播」是原生能力（多图集，≤18 图）；「上下展示」要拼接成长图。所以必须有一条 HTML → PNG 的卡片渲染管线（Playwright 截图）。
  • 通用 HTML：用于站内预览、导出、第三方站点。

如果你的目标账号是个人订阅号，那么公众号侧的产品承诺只能是「一键推送草稿箱 + 后台一键发布」，把 AI 能做的 90% 自动化、保留 10% 人工确认。小红书的自动发布则明确建议不做——连浏览器插件式模拟发布都应回避，因为小红书的风控判定看的是「行为特征」（话术模板化、发布间隔固定、多账号雷同），而不是「是否用了某个工具」，无法通过技术手段规避。产品应改为输出「小红书素材包」（图集 PNG + 标题 + 正文 + 话题标签，一键下载/ZIP 导出），由用户在官方创作服务平台发布。

对本项目最重要的借鉴：本地浏览器通道

Wechatsync 给出了一条绕开开放平台资质门槛的合规路径：把「发布执行」下沉到用户本地浏览器（扩展 / 本地代理），让平台看到的是正常浏览器请求而非服务器 IP 批量调用。

对你的产品来说，这可以设计成一个 「本地投递代理（Local Bridge）」：服务端生成物料 → 本地代理承接 → 调用平台前台接口写入草稿箱。这既解决了公众号个人号的草稿投递，也把凭证（Cookie）留在用户机器上、不必落库——同时解决了合规与安全两个问题。建议列为 P1 核心架构决策之一。

功能为什么必须补优先级
AI 生成内容标识 小红书强制要求：AI 生成/辅助的内容必须在发布时勾选标识，绘图占比 ≥70% 建议加 #AI创作 标签。未标注首次即限流 7 天、扣信用分。产品应默认开启并写入文案尾部 P0

凭证健康监控 平台 Token 会在 60–90 天过期或改密码后立即失效，且不会通知你——只会静默发布失败。需要定时探活 + 到期前告警 P1
素材版权与来源标注 你的主题模型里有「来源」和「时期」字段，这天然是版权与事实追溯的抓手。建议强制填写来源，并保留原图与处理图两版 P1
平台能力矩阵页 把「个人号能做什么、不能做什么」直接展示给用户，避免把平台限制误判为产品缺陷 P1
LLM 成本计量与降级 按主题/用户计量 token 消耗；主模型失败时降级到备用模型。你已有 DeepSeek 集成经验，可直接复用 P2
内容版本与回滚 AI 生成结果需要「重新生成 / 局部改写 / 回到上一版」。没有版本管理，用户不敢用 AI 生成 P2
导出与迁移 主题资产应能导出为 Markdown / JSON / ZIP（含图片），避免数据被锁在产品里——这既是用户信任，也是你的护城河之外的安全垫 P2
